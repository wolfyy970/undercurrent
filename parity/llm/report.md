## Documented deviations

### bash-2q — `${2:?msg}` bash-builtin error text on a missing/empty flag value (11 scenarios; fields allowed to differ: stderr)

The Bash relies on `${2:?message}`, which prints `<script>: line N: 2: <message>` and exits 1. The port prints `llm: error: <message>`, exit 1. Exit code, stdout (empty), on-disk state and requests (none) match; only the stderr phrasing differs, on a misuse path no caller inspects. Same deviation as mem/skills.

### jq-messages — `-M` that jq cannot consume (3 scenarios; fields allowed to differ: stderr, status)

Invalid JSON, or a non-array with `-s`, makes the Bash die inside jq (`jq: parse error …` / `… cannot be added`, exit 5). The port dies `llm: error: --messages is not valid JSON` / `… must be a JSON array (cannot prepend the system message)`, exit 1. No request, no state on either side.

### transport-text — transport-failure wording on the streaming path (3 scenarios; fields allowed to differ: stderr, state)

Where the Bash relays curl's own text (`curl error: curl: (7) Failed to connect …`, `(18) transfer closed …`, `(28) Operation too slow …`), the port says `request failed: <node detail>`. stdout (including any partial streamed output), exit code, retry count and the health-marker `kind` are identical; only the message text (stderr + marker `message`) differs. The non-streaming path never carried curl's text (`HTTP 000`) and is at parity.

### jq-crash-nonjson-200 — non-JSON 2xx body on the non-streaming path (1 scenario; fields allowed to differ: stderr, status)

The Bash's `embedded_err=$(check_response_… < body)` fails inside jq on a body that is not JSON, and `set -e` aborts the script: exit 5, nothing on stdout or stderr, no health marker, no retry. The port fails at the same point, also without a marker or retry, but honestly: `llm: error: API error: response body is not JSON (HTTP 200)`, exit 1.

### jq-stderr-noise — jq parse-error noise on an unparseable SSE event (1 scenario; fields allowed to differ: stderr)

On a `data:` event that is not JSON the Bash's per-delta jq prints `jq: parse error: …` to stderr and extracts nothing; the port extracts nothing silently. stdout, exit code, retries and state are identical.

### connect-timeout-approx — LLM_CONNECT_TIMEOUT bounds a broader window than curl's own connect phase (0 scenarios; fields allowed to differ: stdout, stderr, status, state, requests)

curl's `--connect-timeout` bounds ONLY the TCP+TLS handshake; fetch (undici) exposes no connect-phase hook without a custom Dispatcher, which would need the `undici` package as a new dependency this port doesn't take. Approximated instead as "time until fetch() resolves" (connect + TLS + request-send + time-to-first-byte). Against a server that accepts the TCP connection instantly but is slow to respond (this scenario: local socket connects immediately, headers delayed), the Bash's connect-timeout never fires (the connect phase itself was fast) and the call succeeds once the slow response eventually arrives; the port's broader timer fires at the same deadline and aborts the call. Once headers DO arrive before the deadline, the two are identical (LLM_MAX_TIME/LLM_SPEED_LIMIT govern the rest either way) — see the non-deviation scenarios.

### usage-field-shift — usage record with a missing leading/middle token field (1c: 1fdeb97 adds a 4th @tsv cell) (3 scenarios; fields allowed to differ: state)

`IFS=$'\t' read -r _u_in _u_out _u_think _u_cache <<<"$_u"` inherits the same pre-existing bash bug already documented for the 3-field row (`usageOpenAI`'s PORT-NOTE): `IFS=$'\t'` is a single WHITESPACE character (tab), so `read` collapses consecutive/empty delimiters instead of preserving empty fields. cache_tok's new 4th cell means this now also fires whenever the 3rd cell (think_tok) is EMPTY and cache_tok is present: the Bash shifts the cache value into think_tok and reports no cache_tok at all. This hits the shared `read`-based non-streaming path for ALL THREE providers (anthropic|opencode's think_tok cell is ALWAYS the literal "" on that path, so it is ALWAYS lost there whenever cache_tok is reported), plus the OpenAI/Gemini STREAMING paths (which use the same `read` pattern) whenever the provider omits reasoning_tokens on a cached call. Anthropic's STREAMING path is immune (a separate code path assigns each field from its own dedicated jq call, no positional `read`). The port keeps every field in its own slot (jq-shaped reads throughout, never a positional `read`), so it always reports both fields correctly.

## Notably PARITY (quirks replicated, not fixed)

- prompt = ALL remaining argv joined by spaces once the first non-dash arg is seen (later flags included); an empty first positional still starts it.
- `--thinking` greedily swallows the next argv (even the prompt) unless it starts with `-` or is empty; bare `--thinking` and `--effort` are silent no-ops on this family; `--raw` is ignored while streaming.
- `-M` wins over a positional prompt (silently dropped); a non-array `-M` without `-s` is sent verbatim.
- stdin prompt has ALL trailing newlines stripped; whitespace-only stdin is "No prompt".
- model/provider/endpoint texts, the mismatch warning (also when `--provider` equals the env value), host-only URL warning (credentials/fragment stripped), `opencode-go/` prefix strip, typo'd-provider ordering (both warnings + the non-numeric max-tokens warning print before the die).
- max-tokens table byte-for-byte via the payload (incl. `claude-opus-4-8` → 4096 fallback, `max_completion_tokens` for gpt-5*/o-series, opencode-go tiers, openai-compatible 16384 default, known names keeping their caps).
- streaming: newline-only deltas, CRLF, comment lines; a streamed 4xx JSON body IS retried; whitespace-only stream body → `API error:` + raw lines with trailing newlines stripped; empty stream → "empty response"; a pre-data buffered line beats the stall abort as the error (`API error: : keepalive`); mid-stream failure after output → partial stdout, exit 1, no retry.
- non-streaming: text + ONE newline; `--raw` raw body; missing content prints nothing at all; a non-JSON 200 crashes the Bash inside jq (exit 5, silent, no marker) where the port dies loudly — the documented jq-crash-nonjson-200 deviation, not a success; embedded errors (`.error`, choice `.error`, `finish_reason:"error"`) retried then fatal WITHOUT touching the health marker; whitespace/empty 200 → "whitespace-only response body"; truncation delivered + warned; `HTTP 000` on connection refused / LLM_MAX_TIME.
- on-disk: pretty-printed health marker with kind classification (402/401/403/429 codes beat words; words as fallback; `http_code` number|null); compact ledger line with ts/provider/model/usage/identity/run_id (identity = IDENTITY_NAME or basename IDENTITY_DIR; run_id = LLM_RUN_ID or SHELLM_RUN_STEP_ID; `LLM_USAGE_LEDGER=/dev/null` disables); `LLM_USAGE_FILE` gets `{}` on a non-streaming call whose provider reports nothing (no ledger line), is left untouched by a stream without a usage chunk, and is RE-READ for the ledger (a stale pre-existing record gets ledgered — quirk kept); no temp files left behind.
- .env layering: cwd `.env`, then the state home's `.env`; fill-only-missing (set-but-empty counts as set); cwd `.env` may set `HEADLONG_HOME`; `SHELLM_HOME` and `$HOME/.headlong` fallbacks.
