- Node: `node parity/mem/run-parity.mjs` (Node 24). Locale pinned `LC_ALL=C`.

Slow-model scenarios hold that reply back (transport delay fixtures). Everything else is a no-model layer.
- Normalized symmetrically before compare: `<TS>` timestamp, `<DT>` created/updated, `<HEX>` random id. All else exact.

## Interpretation of divergences

Two root causes — the deliberate `${2:?}` stderr-wording deviation — (plus the job-control notice, item 4) across all mismatched scenarios. Nondeterministic fields are normalized, so every other scenario is a byte-exact match of stdout, stderr, exit code, and on-disk bytes.

1. **`${2:?msg}` bash-builtin error text** (`dir-missing-value`, `list-type-missing-value`, the `empty-required` group `add-type-empty-dies` / `list-type-empty-dies` / `list-before-empty-dies` / `dir-empty-dies` / `edit-slug-empty-dies`, and — upstream sync 2, lane C — `prefilter-top-missing-value` and `add-until-missing-value-dies`) — on a missing OR empty flag value the real tool relies on bash's `${var:?message}` expansion, which prints `<script>: line N: 2: <message>` and exits 1. The port prints its own `mem: error: <message>` and exits 1. **Exit code (1), stdout (empty), and on-disk state (unchanged) all match; only the stderr phrasing differs**, on a misuse path no Headlong caller inspects. Deliberate DEVIATION (bash text embeds the script's absolute path + a Bash line number — irreproducible from TS and brittle to pin); PORT-NOTE in src/mem.ts and PARITY.md. Low severity.

   **M1 fix (upstream sync 1b):** the `empty-required` scenarios were previously HARD divergences — `required()` accepted `""`, so an empty flag value silently ran to completion (rc 0, wrote/renamed corrupt state). `required()` now rejects `""` like bash's `${2:?}`, collapsing those to the same benign stderr-wording-only deviation above (exit + stdout + state now match).
