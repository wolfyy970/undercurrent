# skills — differential parity proof

Generated by `parity/skills/run-parity.mjs`. Real Bash tool `headlong/bin/skills` vs TS port `headlong-ts/bin/skills.mjs`, identical inputs, diffed stdout+stderr+exit code+on-disk state.

- One-command run: `. ~/.nvm/nvm.sh && nvm use 24.19.0 && node parity/skills/run-parity.mjs` (Node 24).
- Bash run under `en_US.UTF-8` so its char-based `${#s}`/`${s:0:57}` match the port's char-truncation (paired with byte-padding — a documented Headlong quirk).
- `curl` (GitHub search fallback) and `git` (remote clone) STUBBED on PATH — identical for both tools — so network paths are exercised deterministically.
- HOME pinned into each sandbox; skill sources/remotes seeded at relative paths. No absolute path leaks; each side's sandbox path normalized to `<SB>` symmetrically. All else byte-exact.

## Result

- **Byte-identical parity: 87/95 (91.6%)**
- Effective parity (identical + documented deviations): 95/95 (100.0%)
- Suspected PORT BUGS / behavioral divergences (translator lane must fix/justify): 0
- Deliberate stderr-wording deviations (misuse paths; exit+stdout+state all match, only stderr text differs): 7
- Robustness deviations (real bash `set -e` crashes the port smooths over): 1
- Unexpected mismatches: 0

## Divergences (detail)

### global / dir-missing-value — bash-quirk deviation
- argv: `["--dir"]`
- note: DELIBERATE DEVIATION (resolved). The flag-parse loop is now wrapped in a try that routes req()'s SkillsError through fail(): clean `skills: error: --dir requires a path`, rc 1, empty stdout, on-disk state unchanged. Matches Bash on exit code + stdout + state; DEVIATES only on stderr wording — Bash's `${2:?}` shell-builtin prints `bin/skills: line N: 2: --dir requires a path` with an absolute script path + Bash line number, which is brittle and irreproducible from TS and worse than the port's uniform error form. Prior port defect (uncaught Node stack trace from the flag loop, outside the dispatch try) is fixed. Documented in PARITY.md. Affects all req()-guarded flags: --dir/--remotes/--format/--name/--description.
- exit: bash=1 ts=1
```
    stdout: MATCH
    stderr: DIFFER
      bash: "<HEADLONG_ROOT>/bin/skills: line 582: 2: --dir requires a path\n"
      ts  : "skills: error: --dir requires a path\n"
    state: MATCH
```

### remove / empty-stdin-cancel — bash-quirk deviation
- argv: `["remove","gone"]`
- note: REAL BASH CRASHES: with empty/EOF stdin, `read -r reply` returns non-zero → `set -e` aborts (rc=1) BEFORE the `|| { echo Cancelled; }` runs, so no 'Cancelled.' and the skill is NOT removed. The port treats EOF as an empty (non-Y) reply → prints 'Cancelled.' rc=0. Same on-disk result (kept), but stderr+exit diverge.
- exit: bash=1 ts=0
